# Feature Lens — ウェブカメラ特徴点ビューアー

## PCなしでiPhoneから使う（v1.7）

[Feature Lensを開く](https://minxlynx.github.io/webcam-feature-viewer/)をiPhoneのSafariで開きます。「オフライン利用の準備ができました」と表示されるまで通信を維持し、Safariの共有メニューから「ホーム画面に追加」を選びます。ホーム画面のアイコンから**一度オンラインで起動して同じ準備完了表示を確認**してください。その後はPCを起動せず、通信がない場所でもカメラ・写真・動画の特徴点抽出、追跡、画像合成、PNG / JSON保存ができます。動画と写真は毎回iPhone上で選び直します。アプリは入力ファイルを保存しません。

新しい版が公開されると「新しい版に更新」ボタンが出ます。作業を終えてから押してください。更新ファイルがすべて揃うまでは旧版を使用します。端末の空き容量不足などでアプリの保存データが削除された場合は、オンラインで再度開いて準備完了を確認してください。実機Safariでのオフライン動作は公開後に確認が必要です。

### GitHub Pagesへの公開

公開リポジトリは [MinxLynx/webcam-feature-viewer](https://github.com/MinxLynx/webcam-feature-viewer) です。GitHub Pagesの配信元はGitHub Actionsです。`main` への送信でテスト、静的ファイルの作成、Pagesへの配信が実行されます。公開サイトに配置するのは `dist/` に作るアプリのファイルだけです。アプリのURLは `https://minxlynx.github.io/webcam-feature-viewer/` です。

手元で静的ファイルを確認する場合は `npm run build:pages` または `node scripts/build-pages.mjs` を実行します。証明書と秘密鍵を含む `.local-https/`、テストの生成物、`dist/` はGitの対象外です。GitHub上ではリポジトリの**ソースコードが公開**されます。写真・動画・カメラ映像は公開されず、解析はiPhoneのブラウザーで行います。

PC上で使う従来の `start.bat`、同じWi-Fiから使う `start-iphone.bat` も継続して利用できます。

### ファイル選択の待ち時間と滑らかさ（v1.7）

iPhoneの写真ライブラリで「送信」を押してからアプリに戻るまでの時間は、Safari・写真ライブラリ側のファイル準備です。形式変換、一時コピー、iCloudからの取得などが発生する場合があります。アプリは `change` イベントでファイルを受け取ってから端末内で解析し、アップロードしません。写真ライブラリの変換はWebアプリから確実には停止できません。[WebKitのファイル選択処理](https://github.com/WebKit/WebKit/blob/main/Source/WebKit/UIProcess/ios/forms/WKFileUploadPanel.mm)。

長い動画では、写真アプリの共有から「ファイルに保存」して「このiPhone内」に置き、Feature Lensの **「保存済みの元ファイルを開く」** →「ファイルを選択」から選んでください。写真ライブラリの変換を経由しない方法です。ファイルを保存する段階やiCloudから取得する段階の待ち時間、Safariが作る一時コピーは残る場合があります。選択画面を開く間は解析と入力動画の再生を休止し、キャンセルすると再開します。選択後は動画全体の先読みを要求せず、情報と最初のフレームを読み込みます。未確定の再生時間のために動画末尾を探索する処理は、長さがInfinityとなるWebMの場合に限定しています。

**「滑らかさ」** で最大60fps（初期設定）または最大30fpsを選べます。カメラにも選んだフレームレートを要求します。表示タイミングのずれで余分にフレームを飛ばしていた待ち方を修正し、同じ動画フレームの重複解析を避けています。24fpsの動画の解析は原則24fps、30fpsの動画は30fpsが上限です。画面のリフレッシュレート、Safariの省電力動作、カメラ、高解像度の設定、処理時間によって実際のfpsは下がります。

表示用画像の毎フレームのコピーをバッファの交換に置き換え、数値表示の更新は約7回/秒に減らしました。画像合成では、通常の検出と範囲内の検出で同じ輝度画像・計算結果を再利用します。PC上で480×270の同じ画像を30回測定した比較では、通常検出の中央値が9.91msから8.60ms、合成用の検出が14.43msから9.29msに短縮されました。検出座標は維持しています。これはPCでの検出部分の比較であり、iPhoneでの実fpsは未計測です。

ウェブカメラ・動画・画像から角や模様の特徴点を抽出し、その位置を表示するローカルアプリです。Windows の Chrome / Edge と、iPhone / iPad の Safari 向けの操作・接続方法を用意しています。

## PCから同じWi-FiのiPhoneへ配信する方法（v1.4）

1. PCとiPhoneを同じWi-Fiにつなぎ、PCで **`start-iphone.bat`** をダブルクリックします。接続案内がPCのブラウザーで開きます。
2. 案内に表示された **`http://PCのIPアドレス:8766/`** をiPhoneのSafariで開きます。ポートが使用中の場合は番号が変わるため、表示されたURLを使ってください。
3. 初回は案内の「接続用プロファイルをダウンロード」を押し、iPhoneの「設定」→「一般」→「VPNとデバイス管理」で **Feature Lens Local …** をインストールします。証明書名がPC側の案内と一致することを確認してください。このPCで作成したプロファイルなので「未署名」と表示されます。
4. 「設定」→「一般」→「情報」→「証明書信頼設定」で同じ証明書を信頼する設定をオンにします。[Apple公式の説明](https://support.apple.com/ja-jp/102390)。
5. Safariの接続案内に戻り、**「アプリを開く」** を押します。アプリのURLは **`https://PCのIPアドレス:8443/`** です。「カメラ開始」を押してカメラを許可してください。

この接続方法を使う次回はPCで同じ起動ファイルを開き、iPhoneでアプリのHTTPSアドレスを開くだけです。Safariの共有メニューからホーム画面に追加できます。**この接続方法では使用中もPCの起動ウィンドウを開いておく必要があります**。PCなしで利用するには上のGitHub Pages版を使用してください。

- **背面／前面カメラ**：iPhoneでは背面を初期選択します。プレビュー下の「前面／背面」で切り替えます。前面は鏡のように反転し、背面は反転しません。端末で取得できる向きを優先要求するため、実際に選ばれたカメラは端末側の対応状況に依存します。
- **写真・動画**：「動画・画像ファイルを入力」で写真ライブラリやファイルから選択します。iOS 17以降のSafariでHEIC / HEIF、JPEG、PNG写真、およびiPhoneで撮影したMOV / MP4（H.264 / HEVC）動画を読み込みます。合成用画像もHEIC / HEIFに対応します。ファイルの種類が空欄や汎用形式でも拡張子から判別し、変換・アップロードせず端末内で読み込みます。動画は最初の映像を確認してから一時停止状態で開きます。Live Photosは選択された写真または動画部分を扱い、動きと写真の組み合わせを再現しません。iCloudのファイルは先に端末へダウンロードしてください。特殊な編集形式や破損ファイルは読み込めない場合があり、その場合は説明を表示します。WebP / WebMなどもブラウザーが対応する場合に読み込みます。

  [Safari 17のHEIC対応（WebKit）](https://webkit.org/blog/14445/webkit-features-in-safari-17-0/) / [Appleの動画形式の説明](https://developer.apple.com/documentation/technologyoverviews/video)。iPhone実機でのHEIC / HEVCの最終確認は未実施です。
- **画像合成**：「04 画像合成」→「範囲を選択」を押してプレビュー上の物体を指で囲みます。選択時は映像を固定し、プレビューまで自動で移動します。画面内の「キャンセル」で戻れます。
- **保存**：「画像を保存」または「座標を保存」の後、「共有して保存」から写真／ファイルへ保存できます。PNGの準備後にもう一度タップする方式です。共有非対応のブラウザーやファイルは通常のダウンロードになります。
- **負荷調整**：初期状態は480px解析・最大250点です。「高精細プリセット」も利用でき、動作が重い場合は「軽量プリセット」で戻せます。iPhone / iPadはメモリ消費を抑えるため、表示と保存PNGを長辺2048px以内に縮小します。入力解像度の表示は元ファイル／カメラのサイズです。
- **座標**：JSON v5の `image` と座標は表示・保存PNGのサイズ、`input` は元の入力サイズです。元入力の座標は `x × input.width / image.width`、`y × input.height / image.height` で求められます。反転前の座標です。
- **画面の回転・復帰**：カメラの縦横サイズが変わると物体選択を解除します。別アプリから戻って映像が止まった場合は「カメラ開始」を押してください。

### iPhone接続の補足

カメラには信頼されたHTTPS接続が必要です（[MDN](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)）。通常の `start.bat` はPC自身から使うためのHTTP起動です。接続案内のHTTPページではカメラを使用しません。

専用ランチャーはWindows PowerShellとNode.js 20以上を使い、追加パッケージなしで証明書を生成します。Windowsの証明書ストア・ファイアウォール設定は自動変更しません。Node.jsのネットワーク接続確認が出たら、利用するプライベートネットワークで許可してください。ゲストWi-Fiや組織の管理ネットワークでは端末間通信が制限される場合があります。

証明書とサーバー秘密鍵は `.local-https/` に保存されます。このフォルダーを共有・公開しないでください。証明書を追加発行するためのCA秘密鍵は保存せず破棄します。アプリ用HTTPSと接続案内用HTTPはLAN向けに待ち受けますが、決められたアプリファイルと公開証明書だけを配信します。入力映像をPCへ送るAPI、アップロードや外部サービスへの送信はありません。

IPアドレス変更や証明書期限切れ時は起動時に証明書を再作成します。その場合は新しいプロファイルをiPhoneに設定してください。古いものや不要なプロファイルは「VPNとデバイス管理」から削除できます。証明書警告が出る場合は警告を無視せず、URLと証明書の信頼設定を確認してください。

開発時にはHTTPSの証明書検証、接続案内、ファイル配信制限、およびChromiumのiPhone相当画面・タッチ入力による動作を自動テストしています。**iPhone実機のSafariでは未検証です**。

## 追跡点数・急な動きへの改善（v1.3）

- 追跡軌跡と移動ベクトルの固定250点制限を廃止し、「最大特徴点数」の設定（最大3000点）を追跡にも使用します。追跡前の新しい検出点も表示するため、対応が未確定の点が画面から消えません。矢印・軌跡は対応を確認できた点だけに描画します。
- 検出後に追跡側でも広い間隔で間引いていた処理を修正し、近接した重複だけを除きます。点数・追跡数・対応数は別々に表示します。
- 画像合成は離れた2点から開始できます。残った点が1点の場合は、対象の見た目も一致するときに限り、回転・大きさを維持した移動だけの追跡に切り替えます。
- 選択対象の周辺では弱い特徴も検出し、信頼できる対象範囲内で特徴点を補充します。最初の特徴点が減っても、初期点数に対する割合だけでは追跡を打ち切りません。
- 動きの予測を使った多段階の追跡に加え、選択時の見た目を基準に画面内を再探索します。急な位置変化や一度隠れた対象も、画像照合が十分に一致すれば自動で再捕捉します。
- 一時的に見失ったときは最大300ms・8解析フレームまで推定位置を表示します。**黄色の破線枠は推定中**です。確かな対応が戻ると緑の枠に戻ります。長く見失った場合は合成を非表示にし、再探索を続けます。

完全に無地の領域、同じ模様が多数ある場面、長い遮蔽、大幅な見た目の変化では位置を特定できない場合があります。曖昧な一致では自動復帰せず、範囲の選び直しができます。表示点数を増やすほど負荷が増えるため、FPSが下がる場合は解析サイズか点数を調整してください。

## ファイル入力と物体への画像合成（v1.2）

1. 「映像ソース」の **「動画・画像ファイルを入力」** からファイルを選ぶか、カメラ／デモを開始します。
2. プレビュー上部の **「04 画像合成」** を選びます。
3. 「物体に画像を重ねる」の **「重ねる画像」** でPNG・JPEGなどを選びます。透過PNGに対応し、未選択時はサンプル画像を使います。
4. **「範囲を選択」** を押し、プレビュー上で対象の物体をドラッグして囲みます。範囲選択中はプレビューを固定し、動画は一時停止します。選択完了後は元の再生状態に戻ります。Escまたは同じボタンでキャンセルできます。
5. 物体の移動・回転・拡大縮小に合わせて画像を重ねます。不透明度、大きさ、縦横比の保持／範囲いっぱいの表示を調整できます。
6. **「画像を保存」** で、その時点の合成画像をPNG保存します。必要に応じて「特徴点を表示」「追跡枠を表示」をオフにしてください。

### 入力ファイル

- 画像：PNG / JPEG / WebPなど、ブラウザーがデコードできる形式。静止画像として解析し、設定変更時に再解析します。静止画像上の選択範囲にも画像を配置できます。
- 動画：MP4 / WebMなど、ブラウザーが対応するコーデックのファイル。読み込み後は最初のフレームで一時停止し、プレビュー下のボタンで再生・一時停止、スライダーでシーク、チェックボックスでループできます。音声は再生しません。
- ファイル入力時は左右反転をオフにします。必要なら表示設定で再度オンにできます。入力解像度の要求はカメラ・デモ用です。ファイルは元サイズで読み込み、解析用の画像だけ縮小します。
- 解析画像は縦横とも最大1920pxで縦横比を維持します。出力PNGはPCでは入力サイズ、iPhone / iPadでは長辺2048px以内です。長さが確定できない動画ではシークを無効にし、長さを「—」と表示します。
- 入力や重ねる画像は端末内で処理します。ファイルの外部アップロードは行いません。入力切り替え・停止時に読み込み用URLと動画を解放します。

### 追跡の仕組みと範囲

画像合成では選択範囲内の特徴点を最大200点追跡し、外れ値に強い相似変換の推定で**平行移動・画面内の回転・一様な拡大縮小**を求めます。開始には離れた2点以上が必要です。背景をなるべく含めず、角や模様が複数ある物体を選んでください。合成画像は解析入力に混ぜず、元の映像の特徴点だけを追跡します。画像照合の方式の参考：[OpenCVの正規化相関によるテンプレート照合](https://docs.opencv.org/doc/doxygen/html/de/da9/tutorial_template_matching.html)。

対象を見失った場合は短時間の位置補完と自動再探索を行います。物体の種類の認識、透視変形・奥行き・隠れた部分の復元には対応していません。横向きへの大きな傾き、長い遮蔽、大幅な見た目の変化では再選択が必要になることがあります。カメラの範囲選択は対象を静止させて行うと安定します。

入力・解析サイズ・方式・デモの変更、シーク、動画のループで位置が飛んだ場合は選択を解除します。「選択を解除」「追跡をリセット」でもやり直せます。停止中は最後に完成した合成フレームを保持します。出力は静止画PNGと解析JSONで、合成動画の書き出しは含みません。

JSON v4には動画の時刻（秒）、対象の追跡状態、選択範囲と変換、追跡方式・補充点数を含みます。`coasting` は観測が確認できていない推定状態、`appearance` は画像照合で復帰したフレームです。物体の範囲・変換は解析画像のピクセル座標で、元画像への変換式も出力内に明記します。

## 追加した技術デモ（v1.1）

プレビュー上部のタブで切り替えます。停止中にタブを選ぶとカメラ不要のデモを開始します。カメラ使用中は同じカメラ映像でデモを実行します。

| デモ | 表示するもの | 試し方 |
| --- | --- | --- |
| 01 追跡軌跡 | 同じ特徴点のIDを維持し、直近24解析フレームの軌跡を色分け | 回転する図形、または模様のある物をゆっくり動かす |
| 02 移動ベクトル | 対応する特徴点の移動を4倍の長さの矢印で表示。x/y変位の中央値も表示 | 画面全体の平行移動、またはカメラをゆっくり横に動かす |
| 03 密度マップ | 16×9区画ごとの特徴点数を寒色から暖色へ表示 | 微細な模様、または無地と模様のある領域を比較 |

「デモ映像のパターン」から入力パターンを独立に変更できます。「追跡をリセット」で履歴を消去します。解像度・デモ・入力の切り替え時や、解析が500ms以上途切れた場合も追跡を初期化します。

追跡軌跡・移動ベクトルの上限は「最大特徴点数」の設定に従います（最大3000点）。順方向・逆方向の追跡が一致しない点や、画像の違いが大きい点は破棄し、新しい特徴点を補充します。検出点は追跡対応の有無にかかわらず表示します。速い動き、遮蔽、反復模様、大きな回転では対応を失ったり誤った対応が残ったりすることがあります。物体の認識・3D位置・カメラ姿勢の推定ではありません。

移動量の単位は**元映像のpx / 解析フレーム間**で、反転前の座標系を使用します。FPSが変わると1フレーム間の変位も変わります。密度は検出・間引き後の点が対象です。点数上限や最小間隔に影響され、色は各フレームの最大区画密度を基準にしています。

## 高精細モード

**「高精細プリセットを適用」**でフルHD入力要求・1920px幅解析・最大1500点に切り替えます。

- 入力要求：HD（1280×720）／フルHD（1920×1080）／4K（3840×2160）。カメラは対応範囲内で取得します。切り替え時はカメラを再接続します。
- 解析幅：320／480／640／**960／1280／1920px**。最大検出数は**3000点**。
- カメラの実解像度と実際の解析サイズを別々に表示します。解析幅は入力幅を上限とし、拡大は行いません。
- デモ映像も選択した入力解像度で描画します。「微細な模様」で解析サイズによる違いを比較できます。
- 4K入力も特徴点解析の上限は1920px幅です。PCのPNGは元入力の解像度で保存します。iPhone / iPadでは前述の表示・保存サイズの上限があります。

高精細解析や追跡は処理負荷が増えます。滑らかさを優先する場合は解析幅を480〜960pxに下げてください。FPSは実測値で、フルHD解析で30 FPSを保証するものではありません。

## 起動

1. **`start.bat` をダブルクリック**します。
2. ブラウザーが開いたら **「カメラを開始」** を押します。
3. ブラウザーのカメラ使用確認で **許可** を選びます。

このPCでは既存の Node.js を自動検出します。他のPCでは Node.js 20 以上が必要です。追加パッケージのインストールは不要です。ターミナルからは `node server.mjs --open` でも起動できます。

終了時は画面の「停止」を押してブラウザーを閉じ、起動時のターミナルも閉じてください。映像は保存ボタンを押したときだけ保存します。サーバーの既定アドレスは `http://127.0.0.1:8765` です。使用中の場合は次の空きポートを探します。

## 操作

- **カメラ**：接続済みのカメラを選択。実行中の切り替えにも対応します。
- **デモ映像**：カメラを使わず、回転図形・平行移動・微細な模様の3パターンを解析します。
- **検出方式**：Shi–Tomasi（構造テンソルの最小固有値）または Harris（k = 0.04）。
- **最大特徴点数**：強い特徴から採用する数の上限です。常にこの数が検出されるわけではありません。
- **感度**：高くすると相対しきい値を下げ、弱い特徴も採用します。
- **特徴点の最小間隔**：解析画像上の距離。上げると密集した点を間引きます。
- **解析サイズ**：横幅 320 / 480 / 640 / 960 / 1280 / 1920 px。入力映像の縦横比を保って縮小し、検出座標を元の解像度に戻して表示します。
- **左右を反転**：プレビューと保存PNGに反映します。
- **画像を保存**：表示中の映像と特徴点をPNGで保存します。
- **座標を保存**：最後に解析したフレームの特徴点、スコア、設定、撮影時刻をJSONで保存します。v2では追跡ID・軌跡・移動量・密度の集計も含みます。座標は反転前の元映像の左上を原点とし、右向きがx、下向きがyです。追跡IDは初期化ごとの番号で、別セッションと共通ではありません。
- **停止**：カメラを解放し、最後の解析画像を残します。停止中も画像・座標を保存できます。

FPSは解析結果の更新頻度、処理時間は検出・追跡・密度集計を含むワーカー内の解析時間です。最大約30 FPSで処理を要求し、実際の速度はPC・カメラ・解析サイズによって変化します。非表示のタブでは解析を休止しますが、カメラは「停止」またはページ終了まで使用します。

## 実装と範囲

Sobel勾配 → 5×5窓の構造テンソル → コーナースコア → 3×3非最大値抑制 → 最小距離による間引き、の順に処理します。検出は Web Worker で実行し、画面操作への影響を抑えています。元画像とその検出結果を組にして描画します。

通常モードと密度マップは毎フレームの検出結果を表示します。追跡・移動ベクトルモードは、画像ピラミッドを用いた疎なLucas–Kanade法を自前実装し、順逆追跡の整合性を確認します。方式の参考：[OpenCVのオプティカルフロー解説](https://docs.opencv.org/4.x/d4/dee/tutorial_optical_flow.html)。OpenCV自体への依存はありません。顔・姿勢のランドマーク検出、物体認識、特徴量記述子の生成は含みません。暗い映像・平坦な壁などでは特徴点が少なくなります。

映像はブラウザー内で処理します。外部ライブラリ、CDN、外部への映像送信は使用せず、ローカルサーバーも画像を受け取りません。通常起動はPCのループバックアドレスのみ、iPhone向け起動はLANから接続できるアドレスで待ち受けます。

## 困ったとき

- **権限エラー**：アドレスバーのサイト設定と、Windows「設定 → プライバシーとセキュリティ → カメラ」でアクセスを許可してください。
- **カメラが開けない**：他のカメラアプリを終了し、「既定のカメラ」で再度開始してください。
- **画面が開かない**：起動ターミナルに表示されたURLをChrome / Edgeで開いてください。HTMLファイルの直接起動には対応していません。
- **処理が重い**：「解析サイズ」を320 pxにし、最大特徴点数を下げてください。
- **Node.jsが見つからない**：[Node.js公式サイト](https://nodejs.org/)から20以上をインストールしてください。

ブラウザーのカメラAPIは安全なコンテキストが必要です。PCではループバックURL、iPhoneでは信頼されたHTTPSで開きます。参考：[MDN getUserMedia](https://developer.mozilla.org/en-US/docs/Web/API/MediaDevices/getUserMedia)。

## 開発時の確認

```text
node --test tests/*.test.mjs
node tests/browser-smoke.mjs
```

単体テストは検出精度、既知の整数・小数移動量の復元、追跡の破棄とリセット、履歴の上限、密度集計、フルHD画像の座標を検証します。ブラウザーテストは3種類の技術デモ、フルHD解析、4Kデモ入力、入力幅による解析サイズ制限、保存機能、合成カメラの開始・停止・拒否・遅延許可を検証します。実カメラのハードウェア動作と4K対応は使用するPC上での確認が必要です。

v1.2では、外れ値を含む回転・拡大縮小の復元、対象の追跡喪失、縦長・左右反転の選択座標を追加検証します。ブラウザー上では実際のPNG／WebMファイルを読み込み、透過画像の合成、PNG／JSON出力、動画の再生・停止・シーク、読み込みエラー後の復旧、入力URLの解放を確認します。

v1.3では1000点の追跡・補充、2点だけの追跡、特徴点の補充、約76pxの急な移動と完全遮蔽後の再捕捉を追加検証します。ブラウザーでも250点を超える表示を確認し、140pxの位置変化と遮蔽を含む動画で推定表示・自動復帰を検証します。これらは合成画像・動画の検証条件で、実カメラのすべての動きに対する保証ではありません。

v1.4では証明書チェーンを検証したHTTPSアクセス、プロファイル配信、秘密鍵へのアクセス拒否、モバイル画像の縮小と座標変換を検証します。Chromiumのモバイルエミュレーションで前後カメラ要求、タッチによる範囲選択、共有用PNG / JSON、320px画面と縦横レイアウト、復帰案内を確認します。iPhone実機やSafariの検証の代わりではありません。
